# 1.20 固件业务队列、消息字段与消费者映射

范围：官方 1.20 鼠标/接收器 radio 镜像，已正确恢复 RAM 执行映射后的最终反编译，并以原始 Thumb 指令和初始化数据交叉核对。本报告描述已确认的正常 mode4 业务链；不是完整原源码，也不代表空口或实机验证。本文地址均为十六进制运行时地址。机器可读字段、42 个来源文件 SHA256、9 处入口原字节及来源偏移见 `business-queue-map.json`。

## 已串起的路径

鼠标 `23026CA4 → 2302125C → 23025AB0 → 230215AC` 产生业务、按类别变换及分片入队。接收器 RADIO ISR `23020A00 → 23024190` 验证 mode4 帧并触发 SWI4；向量处理函数 `23021BE4 → 2302455C` 按类别和业务序号去重，然后经 `230254A0 → 23025004` 重组/转换，最后 `23020250 → 230268B0 → 23026D28` 进入 USB HID 队列。

这条已确认的链在 **radio 镜像本身**。application 镜像内看到 IPC 字符串和通道处理并不能直接把它们归属到这六类业务；跨核消息编号的关联目前仍未证明。

## 六队列与条目格式

|项目|鼠标|接收器|
|---|---|---|
|上下文首址 / 每 peer 步长|23002978 / EE0|230033E8 / F84|
|入队 / peek / pop|230215AC / 230214E0 / 2302145C|230208B8 / 230207EC / 2302073C|
|空闲计数 / 初始化|23021488 / 23021528|23020768 / 2302083C|
|写索引 / 读索引|23002AD6 / 23002ADC|2300353C / 23003542|
|六类环容量|32,5,16,32,32,96|32,16,16,32,32,96|
|每条目步长|16 字节|16 字节|
|队列指针表|23002AF0|23003554|

环以一格空槽区分满/空，实际可用容量为 N−1。鼠标六个存储首址依次为 `23002B08,23002D08,23002D58,23002E58,23003058,23003258`；接收器为 `2300356C,2300376C,2300386C,2300396C,23003B6C,23003D6C`。这些是 peer0 的实例，其他 peer 需按上下文布局处理。

|条目偏移|长度|含义|
|---|---:|---|
|+0|1|业务 body 长度 m|
|+1|1|调用者 metadata；所追路径常为 FF|
|+2|1|入队置 0，peek 置 1|
|+3|1|尚未赋予语义|
|+4|1|DMA 长度 m+2；peek 返回此地址|
|+5|1|稍后填写链路头|
|+6|1|`class<<3 | per_class_seq`|
|+7|m|body|

因此从 DMA 帧起点计算，byte2 的 `(b&3F)>>3` 是业务类别，`b&7` 是每类 1..7 循环的序号。它与 byte1 的链路序号/ACK 不同。mode4 的 byte2 高两位另参与运动累计状态标记，不能直接纳入类别。鼠标 class1 入队还会剥掉输入 body 的分片控制字节。

### class0：控制消息

鼠标 `23021C6C` 构造 4 字节 `[2F,新间隔,生效计数BE16]`，生效计数取当前计数加 100。此轮未找到它在 mode4 分支的对应消费者，不把其他模式消费者泛化过来。`23022F70` 构造 6 字节 `[2B,频道/原因标志,总计数BE16,错误数BE16]`，条件包括总数大于31且错误超过总数1/8，或连续错误超过4。接收器 `2302455C` 解析 2B/2C/17；17 的空闲计数来自直接构造路径，不能据此称为一般队列消息。

接收器 `230214BC` 直接入队两条 5 字节 body：`28 + 4字节状态`；`29 + 1字节状态 + 生效计数BE16 + 00`。鼠标 `23022508` 分派 28/29。这些绕过一般业务分片函数。

### class1：运动与 USB 转换

`23026CA4` 的无线分支输入：offset0 按钮 OR 位图；offset1 滚轮累计；offset2..3 X、offset4..5 Y，两个 16 位数在传输结构为大端。X/Y 累加变量是 `230076D6/230076D4`。传感器读取链 `23026DA0 → 23028290 → 2302A8A8` 读取寄存器 16 的 burst，更新原始位移后累加。

mode4 发送路径对运动累计，接收器 `2302455C` 结合 byte2 的高位状态和每类序号计算相对之前累计值的增量，合成分片前缀 0 再交给 `23025004`。输出 USB 基础格式为 `[buttons&7F,00,00,wheel,X_LE16,Y_LE16]`，共 8 字节。`23020250` 还合并 USB 队列繁忙期间的待发状态；不能把基础格式理解成任意情况下其保留字节都固定为零。

传感器底层 `2302AC40` 配置 DMA 地址 `2FC13040/2FC13000`，使用初始指向 `5F9B5000` 的外设指针并等待外设事件。此证据支持外设 DMA，不足以把缓冲区称为跨核 IPC，也未据此认定具体传感器型号。

### class2 与 class4：固定长度软件加密数据

class2 的 8 字节来源 `23006720`；相关 `230277C8` 修改第0字节位图及 bytes2..7 的六个槽位，形状类似键盘报告，但这里不以此代替 HID 描述符核验。class4 来源多个16字节块或构造报告，看到多种子类型，尚未建立完整字段字典。

`23025AB0` 先清零临时缓冲、复制输入，对 class2/class4 固定长度为8/16，再经 `23020E44 → 23020D50` 变换，随后分为6+2或6+6+4数据字节。接收器在**完整重组后**经 `23020128 → 2302003C` 做逆变换；class4 后续强制长度16。class4 的 byte1==31 路径还用 byte2 更新状态并触发 E3 通知。软件算法、表来源和验证分层见 `business-software-cipher.md/json`。

接收器原镜像初始化数据文件偏移 `1CCE0` 的6字节映射表是 `00 00 02 00 01 00`，加载到 `2300048C`。`230268B0` 用类别索引此表，`23026D28` 实际发送：ring0→hid_dev_0/8字节，ring1→hid_dev_1/16字节，ring2→hid_dev_2/8字节。这是 class1/4/2 的 USB 归属依据；不依靠猜测类别名。

### class3：管理与状态

鼠标 `23021278` 构造8字节 `B1 00 BF 00` 加四个状态字节；接收器 `23020250` 读取 B1 的 bytes5/6/7 并触发 E1/E2/E3 状态通知。鼠标 `23025CAC` 发送单字节 A4，类3队列完成回调经 `23025EB4` 触发；`23025948` 发送 `[AC,平均RSSI]`。

接收器 `2302060C` 发送 B1 加五个状态字节，共6字节；`23024CD4` 发送 A3。鼠标 `23025E38` 处理 A3/B1，AC 在一般 checksum 判定前交 `23025948` 特殊处理。接收器 `23024C88` 处理 A4/AC/AB。AC 下行调用者 `23024DB4/23025640` 的确切长度仍需原指令 ABI 复核；本报告不把缺失反编译参数补成已确认常量。完整状态机与字段命名尚未恢复。

### class5：USB 厂商数据通道

接收器 SET_REPORT 回调 `23026D78` 在所定位条件 `param2==3`、hid_dev0、`param4==5A` 时，从主机缓冲跳过首字节复制89字节到 `23002D1D`，唤醒处理。`23026090` 检验 XOR 字段、用高3位选择 peer，构造 `[5A,报告XOR,报告数据…]`，经 `230205C8 → 230251E4` 发送；调用长度由 `23002D21+10` 决定。

鼠标 `23025E38` 在 class5、首字节5A、整条消息加和为0时，将 body+2 复制到90字节 `23003EFC`，body1 保存到该缓冲+58，再标记业务处理。响应由 `230211DC` 组装 `5A + 23003F54 + 数据`，裁去末尾零、长度范围10..90，经 class5 上行。接收器 `23020250` 保存响应至 `23002D1C` 及 `23002D74`，对应 GET_REPORT 路径 `23026C08`。内部90字节结构尚未解成完整命令字典。

## 分片、重组与两种 checksum

上行 `23025AB0`：一般业务每片最多6字节数据，之前放1字节分片控制。下行 `230251E4`：先在**完整业务消息末尾**追加 `-sum(message) mod256`，随后每片最多4字节数据。分片控制 bit7 表示后续还有片，bits4:0 为片索引；这两个重组函数未使用bits6:5。class0直接入队，class1有特殊前缀剥离/补回，不能套用普通格式。

接收器 `23025004` 为每类使用 `23006278+class*80` 的缓冲，鼠标 `230259EC` 使用 `23006850+class*80`。索引0重启；非零索引必须与期望值一致，否则清空索引与累计长度并返回；more位设置时继续等待，最后一片则提交消费者。鼠标完成缓冲为230067D0，类别/长度在2300779B/2300779C。

下行整消息 checksum 与之前恢复的 **mode4 正常上行逐帧附加 checksum** 是不同层：前者在分片前追加、重组后验证；后者保护每个上行 DMA 帧并被接收 IRQ 检查。下行没有相同的 mode4 逐帧附加字节，不代表下行业务没有整消息 checksum。也不能把加和检查称为密码学认证。

## 加密的证据边界

已确认 class2/4 使用完整 XXTEA 更新结构，2/4个小端32位字，32/19轮。两端从相同256字节只读表按连接 BASE1 低4位选16字节记录。不是仅凭一个常量命名算法。主任务已完成128组原始指令差分：两端各64组，覆盖全部16个表项、8/16字节和两种输入；Python 与 portable C 各自匹配原输出。详情见 `business-cipher-original-exact.md` 与 `business-cipher-original-comparison.json`。它验证纯变换入口，不覆盖安装key包装、完整分片调度、空口或认证。
