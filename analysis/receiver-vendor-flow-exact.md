# 厂商命令、无线测试与工作线程接线

2026-10-19，阶段 63。新增 6,144 组官方 1.20 接收器原指令输入、4,729,891 条 Thumb 指令对照全部一致。3,538 组函数完整返回，658 组工作线程执行到下一循环头；两者分别统计，后者不表示线程退出。旧工作线程接口另有 3,072 组回归通过，不重复加计。当前累计 66 个可编译 C11 单元、87 份数据集、208,128 组原指令输入。

## 已接通的实际流程

新增 [receiver_vendor_flow.c](../recovered-code/portable/receiver_vendor_flow.c) 与 [接口](../recovered-code/portable/receiver_vendor_flow.h)，覆盖既有厂商入口 `2302604C`、路由 `23026090`、工作回调 `230205F8`，并继续执行已经恢复的测试和统计处理。

`FE:70/71/F1` 原包装 `2302048C/23020510/23020530` 并非调用测试参数处理后立即返回：后续还调用 `E06D43C(23002C94)` 提交默认工作队列 `23002B18`。本轮执行真实恢复的提交逻辑，包括忙/已排队/不可用、正常入队及实际 CPU 切换边界。只有处理体和提交函数实际返回后，厂商状态才写为2；路由再重新计算校验并清除待处理标记。

`230205F8` 在路由返回后继续执行 `E05C774`，由真实参数和工作标记选择测试模式、初始化及发送/接收/扫频。工作线程新增可选回调接口，把实际 `230205F9` 回调接到该处理体；完成后继续原有 flush/cancel/yield 尾部。旧接口默认仍保留原未知回调边界。

`FE:72` / `23024DB4` 恢复统计设置：比较原16位值与完整入参，更新 `659A` 的两份16位字段，清零 `659E` 的2字节及 `65B0` 的4字节，使用已有真实分片实现发送 class3 的 `AC + BE16(value)`。按新值和原活动标记启动/停止 `23001AD8` 定时器，启动参数为100000和1000。配置写入不等于空口成功，入队失败也不自动回滚设置。

[新流程对照结果](receiver-vendor-flow-comparison.json)逐字节检查全部128 KiB RAM、8个4 KiB外设快照、8字节设备ID和16字节启动信息，同时检查 BASEPRI、真实边界参数及事件次数。725次 RADIO EVENTS_DISABLED 为测试明确提供的外部输入；缺少事件就停在原轮询指令。新数据集没有替换 USB 驱动或未知回调的返回值。

[旧工作线程回归](receiver-worker-vendor-regression.json)包含先前定义的379组显式 USB 返回输入，沿用旧验证边界，不能解释成驱动已恢复。修改前源码保留在 [历史快照](receiver-worker-v1-before-vendor/manifest.json)。

## 仍然保留的真实边界

新数据中包含939次 CPU 切换入口、86次 USB 驱动入口、103次未知工作回调、99次动态日志回调、216次无线事件等待，以及505次未恢复的身份、LED和更新处理入口。没有把这些边界当作成功返回。

身份命令 `230252A4/23025300` 的消息入队及栈内容、LED PWM 驱动链、class10更新处理仍需继续恢复；静态可复用关系见 [依赖映射](receiver-vendor-dependency-map.md)。该映射指出统计清零宽度，和现有存储API的复用位置；其中未保留原指令的跳表目标仍只作为线索。

代码可以在主机上严格编译链接为 `librr_recovered66.dylib`，还不是完整可启动 Cortex-M 固件。本轮未连接接收器、未写设备，也没有空口、并发或真实调度时序验证。
