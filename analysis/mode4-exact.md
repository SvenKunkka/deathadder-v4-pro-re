# DeathAdder V4 Pro 1.20：4Mbps 分支精确恢复（静态阶段）

本报告只覆盖 **协议 mode=4** 的正常收发分支。已恢复两端 DMA 包布局、单向额外校验、部分队列确认/重传和六个调度阶段。不是完整原厂代码、不是完整空口实现；未使用设备写入，也没有空口抓包、目标执行或仿真验证。所有地址为运行地址。权威输入为 `mouse-radio-1.20-final` / `dongle-radio-1.20-final`，相应 GNU 汇编在 `runtime-images`；逐文件 SHA-256 与结构化证据见 `mode4-exact.json`。

## 1. 分支与证据入口

- 鼠标 `23025778` 初始化连接态，调用 `23021AF8(4)`；后者写 `RADIO.MODE=9`。官方 SVD 枚举为 `Nrf4Mbit0BT6`。**协议 mode=4 与硬件 RADIO.MODE=4 不是同一件事**；后者出现在协议 mode=2 选用的分支。
- 鼠标 RADIO IRQ `23021704` 的 `DAT_23002798==4` 分支：C 第240–355行。鼠标 TIMER IRQ `2302243C` 的 mode4 分支：C 第639行起，包含跳转合并后的包构造代码。
- 接收器 TIMER IRQ `23021BBC` 的 `DAT_23003234==4` 分支：C 第453行起；接收器 RX 处理 `23024190`，状态 `0xC`、事件参数 `4`。
- RAM映射：鼠标 flash `0E06C79C -> 23020000`；接收器 `0E05479C -> 23020000`。这使源码所列地址可回溯到原始固件偏移，参见 `ram-mapping.json`。中断向量证据见 `interrupt-map.json`。

## 2. DMA 帧与校验：两个方向不同

以下 offset 从 `RADIO.PACKETPTR` 所指内存第0字节计数；不是未解白化的原始无线电比特流。

| 范围 | 鼠标普通上行 | 接收器普通下行 |
|---|---|---|
| byte0 | 最终 payload 长度 `L+1` | payload 长度 `L` |
| byte1..L | 原 payload（含协议头） | 原 payload |
| byte L+1 | `(-sum(byte1..L)) & 255` | 无本分支追加字节 |
| 硬件 CRC | 由 RADIO 另行处理；接收器先要求 CRCOK | 鼠标 CRCOK 分支处理 |
| 软件附加验证 | 接收器验证负和，成功后将内存 length 减1 | 鼠标 mode4 接收 ISR 未见相同负和检查 |

鼠标证据：`23024BAA..23024BF4`，接收器：`2302427A..230242BC`。接收器收到 `Lwire=0` 拒绝；当 `Lwire=1`，软件期望唯一的 payload 字节为 `00`，得到原 length0。是否被更高层接纳不在此结论内。

**已纠正一个反编译伪象：** Ghidra 的全局变量别名令 C 看起来先计算校验、之后才还原第一个 word。GNU `23024BB8: str.w ip,[r0]` 明确证明全部前4字节先被复制，接着 `23024BD4` 从 byte1 开始累加。恢复代码采用汇编顺序，不照抄该伪 C。

接收器下行 `230248D6..230248F4` 将16字节源缓冲复制到 `23003070` 并设置 PACKETPTR，未追加校验；鼠标接收在 `23021704` 第270–333行以 CRCOK 进入确认路径。不能把上行附加校验泛化到下行或 mode1/mode2。

硬件原配置是5bit LENGTH、最大 payload31；本次恢复的常规发送路径每次仅复制16字节源对象。因此示例编码器把源 payload 限制在15字节内作为明确使用范围，这不是声称固件存在同样的软件边界检查。完整空口的地址、白化、CRC比特打包不由该编码器模拟。

## 3. 字段布局

### 上行头 byte1

| bits | 操作/含义 | 证据 |
|---|---|---|
| 7 | 请求/启用接收回复的标记 | `2302168C` 参数1；调度代码 `DAT_23002A20` 控制 RXEN；接收器回包由 `DAT_23003484` 门控 |
| 6:4 | 链路 sequence，成功回复后递增，8回绕为1 | `2302168C` 参数2左移4；接收器 `230209B4` 取 `(b&0x7F)>>4` |
| 3:0 | 按当前频道取失败计数，饱和到15 | `230221EC`、`230209AC` |

下行头不能套此格式：接收器 helper `230209D0` 的参数2 **左移6**，公式 `(arg1<<7)|(arg2<<6)|arg3`。mode4构造调用时 arg1=1，选中队列数据时 arg2=1；第三项由当前频道上下文读取，helper本身不掩码。尚不将下行 bit6 称为三位序号。

### 已确证的两个短状态体

| offset | 鼠标上行状态 | 接收器下行同步 |
|---|---|---|
| 0 | `06`，含附加校验 | `05` |
| 1 | 上行头 | 下行头 |
| 2 | 独立 body序号，1..7 | 独立 body序号，1..7 |
| 3 | `17` | `1F` |
| 4..5 | `DAT_23002A10`，BE16，未产生普通数据的计数 | `DAT_23005376`，BE16，事件计数 |
| 6 | bytes1..5的负和 | 不存在 |

例：上行源 `05 B2 03 17 12 34` → `06 B2 03 17 12 34 EE`；下行同步 `05 C0 03 1F 12 34`。这是静态测试向量，不是捕获到的真实包。

### motion队列1的部分布局

`23025020..2302513E` 对队列1且 `DAT_230029AC<3` 的路径进行聚合。字段名称来自操作和鼠标上下文推断；字节位置与运算确定。

| offset | 确定运算 | 推断字段名 |
|---|---|---|
| 3 | 与 `DAT_23002A19` 及旧累积值按位 OR | buttons |
| 4 | 加到 `23002686`，8位回绕 | wheel |
| 5..6 | BE16读取，加到 `23002682`，16位回绕，再BE16写回 | X |
| 7..8 | BE16读取，加到 `23002684`，16位回绕，再BE16写回 | Y |

这一分支将输入数据先弹出到缓存 `23002672..7A`，再供后续重发使用；成功回复清空 `23002670..87`。因此不能把所有队列都描述为“确认后才弹出”，也不能把所有 packet.byte3 都称为 opcode。普通鼠标数据的 byte3 在这条路径是按钮字段。

### 特殊短帧例外

`23024A28` 写常量 `0x5502`，对应 DMA字节 **`02 55 00`**，直接设置 PACKETPTR，绕过 `23024BAA` 的普通附加校验路径。条件包括 reportinterval参数=1、slot0或3，以及队列/频道计数条件。它按普通上行负和规则会被拒绝（`55+00 != 0`）；确切用途和接收侧另外处理的可能性尚未闭合。此帧必须保留为例外，不能自动补校验以抹平差异。

## 4. 调度与时序

鼠标 TIMER020 `PRESCALER=5`（`23022E28`），接收器为0（`2302206C`）；两端 BITMODE=2。下表统一保留**各端原始 tick**。观察到分频比32：鼠标周期500与接收器16000相符。未独立闭合源时钟和 DPPI 触发延迟，故不把寄存器时刻当成实测空口发送时间。

### 鼠标 mode4

radio状态：`0x18` idle、`0x19` TX、`0x1A` RX。周期比较0默认500，时钟校正分支改为497或503。初始 slot5，CC2=415。

| CC1比较值 | 进入slot | handler动作 | 后续CC2处理写入的CC1/CC2 |
|---:|---:|---|---|
| 75 | 1 | TX候选 | 140 / 165 |
| 140 | 2 | 请求回复标记为1时进入RX | 220 / 250；reportinterval>=5时CC2=0 |
| 220 | 3 | TX候选；reportinterval>4跳过 | 325 / 350，或390 / 415 |
| 325 | 4 | TX候选 | 390 / 415 |
| 390 | 5 | 请求回复标记为1时进入RX | 470 / 0 |
| 470 | 0 | 跨周期边界的TX候选 | compare0重置 |

compare0选择：reportinterval=1或(=2且 pending标记非0)从75/100开始；其余常见分支从140/165开始；>=5且不是TX状态从390/415开始。slot3相同条件决定是否有325阶段。reportinterval只是内部参数名，不能未经映射直接解释成某个USB回报率。

发送缓冲准备后读取 CC7 的门限（GNU核对）：slot0必须 **>99**；slot1 **<=100**；slot3 **<=250**；slot4 **<=350**；其余slot无同一门限。失败时撤掉TXEN/START订阅并回idle。它们是准备完成检查，不能理解成“在这个时刻才执行射频TX”。

### 接收器 mode4

周期16000。CC1负责状态推进；CC2负责切换下一组 compare、撤销部分订阅并在slot5更新计数/频道。

| CC1比较值 | 进入slot | handler动作 | 后续CC2处理写入的CC1/CC2 |
|---:|---:|---|---|
| 2720 | 1 | RX窗口 | 4640 / 5280 |
| 4640 | 2 | 上行请求回复时TX | 7040 / 8000 |
| 7040 | 3 | RX窗口 | 10720 / 11200 |
| 10720 | 4 | RX窗口 | 12640 / 13280 |
| 12640 | 5 | 上行请求回复时TX | 15040 / 0 |
| 15040 | 0 | RX窗口，装入下一频道 | 周期起点恢复2720 / 3200 |

TX阶段先从队列0..5选首个非空条目；无条目生成 `1F` 同步体。slot2若 CC7>5280、slot5若 CC7>13280，会放弃当前回包。`23023FA4` 对slot0/3设置RXEN订阅，对slot2/5设置TXEN与PHYEND_DISABLE，slot1/4设置STOP订阅。DPPI发布/订阅的原始通道号由初始化动态分配，完整链需要与DPPI图结合。

### 下行同步计数

鼠标见byte3=`1F`时，GNU `23024846..23024898`：

- CC7=166..249：事件计数采用收到的BE16。
- CC7=416..499：采用收到值+1（16位回绕）。
- 其他时间：保留旧值。

范围比较是无符号32位。成功收包时间样本在slot2记CC7，slot5记CC7−250；由4个样本的平均及误差比较驱动±3tick周期校正。此处只恢复数据流与离散门限，未模拟整套时钟闭环。

## 5. 确认、重试与失联边界

鼠标 mode4 RX 中 CRCOK 路径：递增链路序号（7→1），清空失联计数 `23002A0C` 和motion缓存，设置收到回复标记；选中队列索引<6则调用弹出函数，队列>1还有回调。CRC失败路径不推进序号、不清motion缓存，增加频道失败统计并将 `230029D0` 置2。不能将这些单步行为当成完整队列调度模拟。

接收器完整性检查成功后，保存包并提取上行sequence。仅当sequence不同于 `23003483` 时，重置相关miss计数；若先前选中的下行队列<6，弹出该项并推进下行内部sequence。重复sequence仍继续保存包、更新标志和调用 `23021C24`，因此**此函数不能证明所有重复包都被全局丢弃**。应用级去重需要继续沿通知消费者追踪。

两端在slot5尾部增加周期相关计数。鼠标 `23002A0C>=100` 进入停链清理，接收器 `23003470>=100` 对应链路停用；另一数据间隔计数达到200可把连接状态从3改4。100是调度周期阈值，不能说成100个包或100次射频重传；没有经过源时钟核对也不能直接换算成毫秒。

## 6. 可运行恢复片段与验证

- `mode4_codec.py`：上行加/验校验、两个方向各自的头、`17`状态和`1F`同步体、计数同步、准备门限、motion聚合、接收器sequence确认片段。无设备I/O。
- `mode4_test.py`：离线测试；`mode4_test_results.json` 保存实际结果。
- 实际执行通过 **2094条断言**：256个单字节payload穷举；一条固定包的1530种非零单字节篡改均被软件校验拒绝；5组固定向量；截断/HW CRC失败、上下边界、16位回绕、seq7→1、motion累加与确认清空、重复sequence不弹队列。
- 测试还确认负和校验的局限：两字节等量反向变化可保持校验和。因此测试只证明恢复片段与所读运算一致，不证明完整协议安全性或空口互操作。

## 7. 明确保留的未知

完整报告尚不能称为“完整2.4G源代码”。未闭合项包括：所有queue包体与应用命令、完整动态重试与队列竞争、短帧 `02 55 00` 的用途、所有reportinterval分支的可执行状态机、DPPI完整端点图、绝对时钟与空口验证、接收通知消费者是否做完整去重，以及地址/白化/CRC到比特流的完整编解码。没有据此推断不存在加密/认证，也没有把本地单元测试冒充实机验证。
