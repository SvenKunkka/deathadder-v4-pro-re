# 接收器厂商命令分发与无线转发（官方1.20，第59阶段）

新增 [receiver_vendor_commands.c](../recovered-code/portable/receiver_vendor_commands.c) 和 [接口说明](../recovered-code/portable/receiver_vendor_commands.h)，恢复 `2302604C` 分发、`23026090` 校验/转发、`230205F8` 工作包装前段。原有58个C单元未改动。

## 消息与路由

RAM `23002D1C` 保存90字节消息：offset0状态、offset1高3位目标、offset5负载长度、offset6类别、offset7命令、offset8起负载。校验对offset2..87做XOR，与offset88比较；offset0、1、89不参与此校验。

待处理标记 `71BB` 非零才处理。校验失败只把状态设3，保留收到的校验字节，然后清待处理标记。校验正确先执行本地命令分发；若状态仍为1，目标字段0映射peer0，4映射peer1，7映射本地，其余映射255哨兵。查询 `2C80` 对应bit：不可用则状态4；本地bit可用但仍未处理则状态3；peer可用则用 `5A + 原校验字节 + 消息前(长度+8)字节` 调用真实恢复的class5分片发送。

转发队列满时，原代码仍会清待处理标记，状态也可能保持1；不能将其解释为发送成功。其余已处理分支重新计算XOR。恢复API的转发长度域为0..80，超域返回-2；这是分析域边界，**不是原固件长度校验**。

## 已定位的命令行为

下表描述指令实际读写的字段，未擅自赋予产品功能名称。存在调用边界的命令只恢复到该真实入口。

|类别|命令|实际行为|
|---|---|---|
|00|04|目标7时写71BD；满足条件时刷新状态或进入25954，清71B2|
|00|0B|负载1进入25300；3写2D82=FFFF并标记配置变更；5设置完成状态；20608/26F68为原始空函数|
|00|0D / 8D|写/读2DB5的4字节；写操作标记配置变更|
|00|12 / 92|写/读2DB9的20字节；写操作标记配置变更|
|00|15 / 95|写/读2DCF与2D8B身份字段；写入0或FFFFFFFF时回退到设备ID字节序转换值，随后进入252A4|
|00|3C / BC|写/读2DB3的2字节|
|00|45 / C5|根据选择值1/2写/读2D82或2D84的2字节，并保留选择值2DD3|
|00|46 / C6|仅设置状态2|
|00|91 / 93|从官方镜像常量0E06FA70读取2/4字节|
|00|9F|读取0000F000/4/8/C各一个字节|
|00|B8 / BA / BF|返回连接bit及两组2字节字段；保留未写到的负载尾部|
|00|C3|清负载前4字节，设置状态2|
|07|15 / 95|写/读2CB4三字节；写值均需≤4，更新配置副本并刷新3组状态颜色|
|07|17 / 97|写/读2DAA三字节，变更时标记配置修改|
|07|96|读取71B3一字节|
|0F|任意|设置状态2|
|10|任意|进入0E05BE8C，保留真实入参；该处理体尚未恢复|
|FE|33|仅目标7处理，检查71BD和负载，进入25954或25FE0；保留之前的状态写入|
|FE|70 / 71 / F1|分别进入0E05C504/0E05C5EC/0E05C6D4；70/71先置6595=1|
|FE|72|负载前两字节按大端取值，进入24DB4|
|FE|73 / F3|目标7时写/读2D94的22字节；写操作标记配置变更|
|FE|7F|恢复最多40项编码转换到31FC，非法长度关闭31FA，保留旧尾部|
|FE|FA|返回设备ID两字，顺序为0FFFE014、0FFFE010|
|FE|FB|清32字节后填充无线状态字段及RADIO BASE1/PREFIX0静态读值|
|FE|FF|204B8为空函数，只设置状态2|

未知命令通常保留状态并返回，之后仍可能按外层路由转发。00/07/FE各256个命令字均已进入原指令测试；这不等同于穷举所有输入状态。跳表原字节与地址见[命令映射](receiver-vendor-command-map.json)。

配置修改函数26F30只将719E的16位计数清零，并在71BA置bit0（类别2）或bit1（类别4）；没有调用Flash写入，不能据此声称已持久化。

## 验证

[8,704组原指令对比](receiver-vendor-commands-comparison.json)，运行4,211,689条原指令。7,126组完整返回，1,578组停在真实未恢复入口；没有注入外部调用返回值。对比全部128KiB RAM、4KiB RADIO快照、8字节设备ID及16字节启动区快照，并检查边界的有意义参数。

工作包装在路由完成后必经0E05C774；该无参数函数当前保留入口边界，不能说完整工作回调已经返回。原工作线程模块仍保留原契约，尚未自动接入新的vendor入口。

[连续组件验证](receiver-vendor-commands-continuous-comparison.json)：两条peer链路共64次转发、606片，经真实恢复的分片/重组/鼠标消费者写入90字节命令缓冲；64次目标不可用、64次校验失败、2次队列满、64组本地配置写读验证通过。

这里显式复制DMA帧和调用鼠标消费者，没有实际RF、ACK或线程调度；终点是鼠标命令缓冲与标记，未执行鼠标侧完整厂商命令字典。完整2.4GHz代码工程与实机验证目标仍未完成。
