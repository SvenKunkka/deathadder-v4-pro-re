# 接收器消息队列与配置线程入口

本轮把接收器配置处理从“出队后的分派”向前接到真实 `message_get`。恢复 `0x0E06CC94` 的36字节队列语境，以及 `0x23024E46` 开始的一次配置循环；尚未恢复CPU请求后的真实栈续接。

## 已恢复的行为

- 非空队列：复制完整36字节，读指针回绕，减少消息数。
- 如有发送线程在等空位：弹出首个等待线程，取消其timeout，把它的消息立即补入环队列，更新写指针和消息数，置返回结果0并就绪/调度。
- 空队列且不等待：返回`-35`，不改输出消息。
- 空队列且等待：记录输出地址，当前线程从就绪链移入按优先级排列的等待链；有限等待启动实际timeout，永久等待不启动；停在真实CPU请求入口，保留BASEPRI参数。
- 配置循环：实际调用上述出队逻辑，再进入已恢复的配置事件和下一循环头。出队过程需要CPU切换时，不越过边界假装已经返回。

接口见[恢复代码](../recovered-code/portable/receiver_queue_runtime.c)及[头文件](../recovered-code/portable/receiver_queue_runtime.h)。队列接口特化于这里的两个36字节配置/通知队列，不宣称覆盖任意消息长度。

## 原指令比对

新增4,096组输入：2,048组直接队列入口、2,048组配置循环入口，共7,486,183条原指令。1,755组完整函数返回、1,664组下一循环头、635组真实CPU请求边界、42组人工未知stop回调边界。所有比较通过。

比较128KiB RAM、九个外设/标识窗口、完整36字节输出、BASEPRI、边界入口/参数及直接入口的返回值。覆盖满队列等待发送者、空队列已有接收等待者、有限/永久/零等待、时间片、timeout链、消息回绕，以及配置事件1/4/8/9/10/40/41/43/44和默认分支。

初始化PHY仍显式接收旧栈字节：本轮是在原指令真正完成出队后、到达`23024E56`时记录该字节。没有用固定值替换旧栈，也没有把栈残留来源称为已恢复。[完整比对结果](receiver-queue-runtime-comparison.json)及[原字节/来源摘要](receiver-queue-runtime-exact.json)。

## 连续组件验证

另128轮、768条配置消息通过：640条经环队列，128条直接交付等待中的接收线程；128次满队列拒绝、64次有限等待timeout取消、256次显式上下文交接。每条消息的完整36字节、FIFO、回绕和配置值提交均检查。[组件结果](receiver-queue-continuous-comparison.json)。

这组连续测试使用共享RAM消息缓冲代替私有线程栈。CPU交接由测试显式提供；等待返回后的配置段使用已有出队后接口，输入是生产者实际交付的消息，不等于真实CPU异常返回或栈恢复。它不增加原指令输入计数。
