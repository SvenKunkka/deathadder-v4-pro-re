# 接收器 1.20：握手末端通知分支的精确语义

本记录只解释 `230223F0` state 3 接受 `0x16` 后的通知及直接后继，不是完整配对实现。证据为 `dongle-radio-1.20-final` 反编译、原始 Thumb 指令、初始化数据及向量表；未操作设备。地址均为运行时地址，除明确标作 LMA/镜像偏移者。

**结论：`23025580` 向内存队列发送事件 5；已找到并注册的接收线程只处理事件 1、2，事件 5 被取出后直接忽略。`23020BD4(0xFF)` 只清除 RADIO 接收地址使能 bit 0。此路径没有证据表明事件 5 触发持久化。**

## 1. 输入、条件和时序

`230223F0(slot, packet)` 的本分支依次要求：

1. `packet[1] >> 7 == 0`，即最高位为零；辅助函数 `23020988` 直接右移 7 位。调用处使用字节加载。
2. `u16[0x230034B0 + slot*0xF84] == 3`。
3. `packet[3] == 0x16` 且 `packet[0] == 0x0B`。

若上述成立、`u32[0x230033FC + slot*0xF84] != 0`，执行：

1. 构造下面的 12 字节输入，调用 `23025580`。
2. 仅在该函数成功返回后，将当前 slot 的 `0x230033FC` u32 和 `0x23003402` u16 清零。
3. 再读 slot 0 的 `u32[230033FC]` 和 slot 1 的 `u32[23004380]`；两者均为零才调用 `23020BD4(0xFF)`。

随后，无论进入本次通知与否，均将当前 slot 的 `u32[230034B4 + slot*0xF84]` 清零、握手状态改为 6、返回 2。pending 原本为零时不会补发事件，也不会清 `03402` 或修改接收地址使能。条件不符返回 0，握手状态写回原值。

本函数没有 slot 边界检查，恢复实现应将有效 slot（当前双 slot 语境为 0/1）和可读 packet 内存作为外部前置条件。本分支只读取 packet 偏移 0、1、3；`packet[0]==11` 是固件字段检查，不是宿主缓冲区边界检查。

证据范围：`230223F0..2302243C`（入口、状态选择）、`23022568..23022596`（末端条件/返回）、`23022638..2302268C`（通知、清标志、RX mask）。汇编证实清零地址是 `230033EC + slot*0xF84 + 0xC8 = 230034B4 + slot*0xF84`，不采用反编译表达式的模糊指针类型推算。

## 2. 通知的字节格式

`23025580` 的参数指向 12 字节，读 3 个 32 位字；无需接收 packet 指针，也不读取 packet[4..]。

| 输入偏移 | 类型 | 值 |
|---|---|---|
| 0 | u16 little-endian | slot 的低 16 位 |
| 2 | u16 little-endian | 1 |
| 4 | u32 little-endian | `u32[23003244]`，语义未命名 |
| 8 | u16 little-endian | `u8[230033EE+s]<<8 \| u8[230033EF+s]` |
| 10 | u16 little-endian | `u8[230033F0+s]<<8 \| u8[230033F1+s]` |

其中 `s=slot*0xF84`。后两项是把已有身份字段的相邻两字节按高位/低位组成数值，再以小端写入消息；不得直接按原顺序复制这四个字节。

实际队列消息是 **36 字节**：偏移 0..3 为 u32 事件值 5，偏移 4..15 为以上 12 字节；偏移 16..35 是本函数未初始化的 20 字节栈内容。`23025580` 的 `sub sp,#40`、消息地址 `sp+4` 和仅 4 个 word store 可直接确认；不能恢复为固定 16 字节消息，也不能声称尾部为零。纯逻辑实现可将这 20 字节显式标为 opaque/unknown。

## 3. 队列、失败重试与消费

队列对象为 `0x23001B8C`。由初始化数据 LMA `0x0E070854` → `0x23000000` 读取，原镜像偏移 `0x1E3E0`：

| 对象偏移 | 初始值 | 解释 |
|---|---|---|
| +0,+4 | 23001B8C | 空等待链表自引用 |
| +8 | 0x24 | 每条 36 字节 |
| +C | 5 | 最多 5 条 |
| +10,+14 | 23015760,23015814 | 环形缓冲区首、尾后 |
| +18,+1C | 23015760,23015760 | 读、写指针 |
| +20 | 0 | 消息数 |

已检查所有导出 C 对此队列的直接引用与原始镜像中的精确地址常量：消费 `230253C4`；生产事件 1 的 `2302546C`、事件 2 的 `230254F8`、事件 5 的 `23025580`。额外字面量 `0E06C9CC` 是另一个对象区间初始化循环的排他结束地址，不是此队列的重配置。未发现修改消息长度的直接路径；任意未解析间接别名写入不能由此完全排除。

`23025580` 调用链：

```text
23025580
  -> 23027108 -> 0E06CBDC(queue, message, 0, 0)  // 非阻塞放入
  若返回非零:
  -> 230271A0 -> 0E06CD54(queue)                 // 清队列
  再试放入，直到返回 0
```

`0E06CBDC`：读 count/max；有空位时，若存在等待线程，将 36 字节直接复制到等待线程保存的目的地址（thread+0x14），设置 thread+0x8C 为 0 并进入调度唤醒路径；否则复制到环形写指针，推进/回绕指针，count++。满且 timeout=(0,0) 返回 `0xFFFFFFDD`（有符号 -35）。复制例程 `0E06F35C` 是逐字节复制。不要给 -35 自行附加未经 SDK 匹配的 errno 名称。

`0E06CD54`：从等待链表逐个移除线程、设置其 +0x8C 为 -35、进入调度唤醒路径；最后 count=0，read_ptr=write_ptr。它会丢弃队列中全部尚未取出的消息，然后生产函数重试；不是只丢弃最老一条。各队列操作保存 BASEPRI，经 `BASEPRI_MAX=0x40`、ISB 进入临界区，之后恢复或交给调度尾路径。put 与 purge 是不同调用，不应恢复成未经证明的整体原子事务。

`2302532C` 注册 `230253C5` Thumb 入口（对象 23002050、栈 2300FC00、大小 0x400）。消费者 `230253C4` 使用 timeout 两 word 均为 FFFFFFFF 调用 `0E06CC94`，即空时进入等待路径；返回后仅检查事件 1 或 2。**`230253F2` 比较 2，`230253F4` 的不等分支立即回到 `230253DC` 再次接收，事件 5 不读取 payload，不调用存储、IPC 或应用回调。**

这是“已注册的直接消费者忽略事件 5”的确定事实，不是证明所有未来运行时别名/动态改写均不存在。消费循环不检查 get 的返回状态，不能替它添加自动错误处理。异常唤醒或任意并发时序的完整系统效果不在此片段中重建。

## 4. 硬件动作和上层调用上下文

`23020BD4(x)` 修改 `RADIO_S_RXADDRESSES`（`0x5302C000+0xE40 = 0x5302CE40`）：

| x | 清除的 bit mask |
|---|---|
| 0 | 0x0A |
| 1 | 0x0C |
| 2 | 0x06 |
| 7 | 0x80 |
| 其余，包括 FF | 0x01 |

本分支的实际指令是 `ldr [r2,#0xE40]`、`bic #1`、`str [r2,#0xE40]`，地址 `23020BE6..23020BEE`。其直接效果为不再使能逻辑接收地址 0，其他位保持读取到的值；它没有触发 `TASKS_DISABLE`，也没有修改配对地址内容或持久存储。

唯一已定位直接调用者是向量表 `RADIO_0` IRQ 44 对应的 `23020A00`（向量值 23020A01）。可到达条件包括 `u16[23003234]==2`、`EVENTS_DISABLED==1`、全局状态 `u32[23003230]>1`、当前 slot 的无线状态 `u32[23003468+s]==9`、`EVENTS_CRCOK==1`。slot 来自 `u16[230032D0]`，packet 为 `230034BC+s`。

调用 `230223F0` 返回 2 后，caller 在 `23022BB6..23022BC0` 另外调用 `23020F1C(&radio_state, &RADIO_TASKS_DISABLE, 10)`：将无线状态设为 10，清 `EVENTS_READY/END/DISABLED`，向 TASKS_DISABLE 写 1。这属于外层 IRQ 状态推进，不能归因于事件 5 的消费者。后续无线 state 10 分支另有事件 1；本报告不将它与事件 5 合并。

## 5. 可恢复的局部行为片段

下面是顺序语义；`enqueue5_until_success` 必须保留上述 36 字节长度、未知尾部、满时 purge 后重试的约束。它没有模拟 RTOS 调度、真实 MMIO 或执行硬件动作。

```python
def final_handshake_branch(slot, packet, mem, enqueue5_until_success, rx_mask):
    s = slot * 0xF84
    if packet[1] & 0x80 or mem.u16(0x230034B0+s) != 3:
        return 0, rx_mask
    if packet[3] != 0x16 or packet[0] != 0x0B:
        return 0, rx_mask
    if mem.u32(0x230033FC+s) != 0:
        payload = (slot & 0xffff, 1, mem.u32(0x23003244),
                   mem.u8(0x230033EE+s)*256 + mem.u8(0x230033EF+s),
                   mem.u8(0x230033F0+s)*256 + mem.u8(0x230033F1+s))
        enqueue5_until_success(payload)  # packed <HHIHH + opaque 20-byte tail
        mem.set_u32(0x230033FC+s, 0)
        mem.set_u16(0x23003402+s, 0)
        if mem.u32(0x230033FC) == 0 and mem.u32(0x23004380) == 0:
            rx_mask &= 0xfffffffe
    mem.set_u32(0x230034B4+s, 0)
    mem.set_u16(0x230034B0+s, 6)
    return 2, rx_mask
```

此片段对不属于 state 3 的输入仅表示“本分支不处理”，不替代原函数的 state 0/2 分支。恢复代码还应保留未触及字段，不把 u32[23003244] 猜成密钥/序列号/闪存地址。
