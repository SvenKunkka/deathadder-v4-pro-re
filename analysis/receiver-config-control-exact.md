# 接收器配置控制、无线启停和定时器

已恢复出队后的配置事件 **4、10、40、41、43、44**。新增 C 模块与官方 1.20 接收器无线核原指令执行结果逐项比对，5,120 组输入全部通过。这是软件行为恢复，尚未连接接收器，也不是空口通信验证。

## 恢复范围

|事件/入口|实际行为|
|---|---|
|4|挂起无线线程，清无线状态、关闭 DPPI/TIMER/RADIO，再初始化 RADIO、恢复线程和发信号量；到尾段设置状态5|
|10、40|清两字节连接标志；停止两个定时器，按标志启动周期1000的定时器，并启动周期1000000的定时器|
|41|设置连接标志0101及模式1，启用无线，启动周期定时器，设置状态5|
|43|清单字节连接标志；对选中的peer排入class3 A3消息，启动断连定时器并停另三个，最后模式0|
|44|置单字节标志，调整重连定时器，模式1；仅在另一标志非零时启用无线并设置状态5|
|timer start|保留永久等待无操作、相对/绝对时间、原timeout链表和RTC重装副作用|
|timer stop|活动timeout取消后进入真实stop回调，或唤醒首个等待线程；不擅自取消该线程的timeout或清结果字段|
|线程挂起/恢复|实际修改等待/就绪链表、时间片及next指针；需要CPU切换时保留真实入口和参数|

周期与延时为固件传入的计时数值，此表不额外推断实际时间单位。停止回调非零时返回待处理边界；本轮没有从回调后伪造继续执行。

## 原指令验证

10类各512组：四个独立函数、六个配置事件；共执行2,101,359条原指令。2,001组完整函数返回、2,809组到下一配置循环头、91组到CPU请求入口、219组到人工设置的stop回调入口。各项汇总及原字节见[证据记录](receiver-config-control-exact.json)。

比较全部128KiB RAM、RADIO/TIMER/NVIC/DPPI/RTC、三个时钟窗口和设备标识窗口，同时比较BASEPRI及待处理入口/参数。覆盖定时器活动/空闲、等待线程、就绪优先级、时间片、队列满/回绕、不同连接标志及异常上下文。旧栈写入不在比较范围内，外设窗口不会自行推进时间或产生IRQ。

`0x23024FD8`仅作为人工stop回调停止点，未执行该函数，不声称是产品实际注册的stop回调。循环头结束也不等于线程退出。无接收器，不能据此声称射频时序、并发或实际互通通过。

初次比对有10个挂起线程边界不一致，已按外层函数提前返回的原指令修正；[失败记录](receiver-config-control-initial-failure.json)保留。原指令数据没有为修复C代码而更改。另修正`52F0`清零宽度为32位。
