# 接收器存储启动调用链恢复

已恢复第 49 个 C11 单元，连接实际 `23025848 → 23025874 → 0E05E6D4` 路径，并恢复设备就绪检查与分区信息查询。新增 **1,536 组原指令对比通过**，执行 **22,167,549 条原指令**。

## 已接入行为

`23025848` 先更新设备引用 `RAM2CA4` 和就绪标记 `RAM71B0`，随后调用两区初始化。就绪检查 `0E06C6C0` 要求设备非空、状态字节1的最低位为1、状态字节0为0。

`23025874` 先检查设备状态，再查询 A 区 `1DB000` 的页大小，计算 `2000/page_size` 并挂载。A 区成功后再次检查设备状态，再对 B 区 `1DF000` 计算 `3000/page_size` 并挂载。任一步失败统一返回 -22。它不预先清空整个上下文，也不把第一区成功误当成两区均成功。

`0E0673E8` 分区查询按 layout 表计算页起点、大小、索引；offset=0 时按页索引查询。保留32位无符号回绕，以及当前ARM配置下除零产生0的语义。layout为空时只清输出起点和索引，保留原输出的页大小字段。

官方1.20绑定：设备 `0E06F6CC`、状态 `RAM1A1A`、参数 `0E070394`、layout `0E07039C`，实际布局为512页×4096字节。恢复入口使用同一镜像中的layout和稳定16/FF参数。初始镜像的设备状态是 `00 00`，不能据此称为已就绪；更早的驱动初始化仍未接入。

## 验证

[差分结果](receiver-storage-startup-comparison.json)：

- 512组启动路径输入：两个入口各256组。原程序执行实际ready、layout查询、挂载及映射驱动软件体；仅锁操作结果和26次明确的外部设备状态变化在边界提供。
- 512组独立layout查询：显式提供getter输出，涵盖零到五项、空表、零页大小、跨段、越界和回绕；不把修改后的表当成产品真实配置。
- 512组ready检查：遍历状态标志字节、不同错误字节及空设备输入。

全部比较128KiB RAM、2MiB映射快照和返回值；启动路径另比对锁参数和顺序。临时栈排除在比较范围外。原执行中ready入口共命中1601次、page-query共1243次、mount共731次。

[连续组合验证](receiver-storage-startup-continuous-comparison.json)：由恢复代码自行建立两区地址、页大小和页数。空白存储初始化后，192轮写入，每轮清空两区144字节上下文并重新启动存储，共 **193次启动、386次挂载**，384条配置读回和573次辅助键检查通过，身份继续进入配置队列和无线初始化组件。真实设备状态就绪是上游驱动边界输入，锁为显式同步回调；这是存储子系统的主机模拟重启，非整机断电测试。
