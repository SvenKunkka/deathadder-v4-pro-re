# 接收器记录写入、换页与回收（官方 1.20）

配置写回已接到恢复的记录管理层：分块/补齐写入、数据和记录头追加、页代际初始化、换页、有效记录回收及顶层写入。本轮 **4,608 组原指令场景、9,274,428 条原指令**比对通过；另192轮连续写入/读回/无线初始化通过。累计 **46 个 C 单元、65 份数据集、138,624 组原指令输入**。

这些代码操作调用者提供的存储快照。真实互斥锁与存储上电初始化仍是边界；没有执行设备写入或刷机。

## 实现和来源

[恢复源码](../recovered-code/portable/receiver_storage_write.c) · [接口](../recovered-code/portable/receiver_storage_write.h) · [原字节与校验摘要](receiver-storage-write-exact.json)。

|入口|恢复行为|
|---|---|
|0E05DF2C|按设备块大小写完整部分，尾部复制到32B临时缓冲并用擦除值补齐|
|0E05DFA4|数据追加；非负写入结果推进64位数据游标并返回0|
|0E05DFE0|16B记录头追加；仅写入返回0时递减64位记录游标|
|0E05E13C|读取旧页代际，生成FFFF长度/FFFFFFFF key/4201标记头；成功才恢复原记录游标|
|0E05E1BC|填充旧页剩余记录位、关闭记录、切到下一页、取得页代际、重置数据游标|
|0E05E4A8|检查待回收页，只保留仍为最新的有效记录；长数据分块搬移，重算记录CRC8及页代际|
|0E05EB1C|检查ready、长度和容量；调用互斥锁；寻找空间或换页回收；写入内联/长数据/删除记录；释放互斥锁|
|23025924|index只接受0/1；底层返回请求长度或0时，包装结果为true|

`rr_receiver_settings_write_continue` 用该顶层写入实现承接原配置管理state的A/B写回请求，再把实际返回值交还给配置管理层；因此不再需要测试人为指定“记录写入成功”。互斥锁回调仍须由实际运行环境提供。

## 必须保留的原行为

1. 数据追加把非负结果当作可推进；记录头追加仅接受0。错误注入中正返回行为不能统一改成通常的0成功约定。
2. 初始化页头若失败，原记录游标可能停留在页头位置；只有成功才恢复。
3. 换页函数会忽略关闭记录那一次写入的返回值，继续推进页号和读取下一页代际。其余失败仍保留已经产生的副作用。
4. 删除记录长度为0，仍使用key和代际生成记录头；当前位置刚好等于一个slot时也有专门路径。
5. 回收会再次查找同key的最新位置；被新记录覆盖的旧版本不再复制。长数据按最多32B搬移，记录中的数据偏移更新为新位置。
6. 顶层调用互斥锁和解锁后不检查它们的返回值。此处恢复的是原控制流，**不是证明可以省略锁或在未取得锁时继续运行**。

## 设备参数证据

官方镜像中，设备参数指针 `0E067474 → 0E070394` 声明写块大小16，擦除填充值FF；布局指针 `0E067484 → 0E07039C` 的两项为512和4096。`0E0673E8/67468` 的页信息查询将这两项用作页数和页大小，且设备vtable连接到该查询。结合初始化分区长度，镜像配置对应A为2页、B为3页，每页4096B。

这是**匹配官方镜像的静态配置证据**，不是对用户接收器的现场读取或物理擦除粒度测量。错误注入测试另外构造1/2/4/8/16/32块大小，目的仅为覆盖原软件分支。

## 已执行的验证

[驱动/锁边界对照](receiver-storage-write-comparison.json)：4,096场景，覆盖上述8个直接入口各512组。4,283,160条原指令，逐次核对22,152次写驱动、32,552次读驱动、560次加锁和560次解锁；比对每次写入内容、设备/偏移/长度、返回值、最终RAM及存储区。失败时“已写入部分状态”和正返回的原副作用都保留。

[真实映射驱动组合](receiver-storage-write-mapped-comparison.json)：512场景，原记录写入、换页、回收和映射读写软件体实际执行至返回，共4,991,268条原指令；只在互斥锁入口提供明确外部结果。最终128KiB RAM及完整2MiB映射区一致。软件内存模型没有验证实际写入寿命、掉电恢复或并发。

[192轮连续组件](receiver-storage-write-continuous-comparison.json)：384条配置写入并全部读回、192条辅助更新/删除、573次最新值检查；9次页关闭、11次页头写入。随后192次身份消息进入配置队列与无线初始化。写入结果由恢复代码和映射驱动产生，互斥锁回调则明确使用串行测试输入。存储mount上下文和首个页头由测试提供，未伪装成自动上电恢复。

组件测试的页关闭和页头写入数量是运行中观测到的驱动动作，不等同于实机Flash操作。连续组件不加入原指令输入计数。

复验：[边界采样](../ghidra-scripts/EmulateReceiverStorageWrite.java)、[映射采样](../ghidra-scripts/EmulateReceiverStorageWriteMapped.java)、[边界比较](verify_receiver_storage_write.py)、[映射比较](verify_receiver_storage_write_mapped.py)、[连续组件](test_receiver_storage_write_continuous.py)。
