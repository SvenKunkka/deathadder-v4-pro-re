# Frame Sync：鼠标传感器侧静态证据

核验日期：2026-10-20。范围仅限传感器读取、相关 GPIO/定时器、传感器配置与上报数据交接；不扩展通信栈。沿用现有 REA/Ghidra 导出并核对原镜像字节，没有运行固件、headless、写设备或修改 portable C。配套 `frame-sync-sensor-map.json` 保存逐文件 SHA-256、34 段原字节/反汇编、直接调用点、描述符及候选寄存器表。

## 可确认的结论

软件用 P2.04 输入和定时调度提交 `6778` 运动读取工作；工作回调通过软件 CS/P2.07 发起 SPIM132 的 **`0x16` burst 读取**。完成条件是 **SPI DMA END**，不是已识别的传感器曝光结束事件。返回数据里的位移被累积，交给后续报告工作。

`2302B504` 的 `rate×125−95` / `+30` 定时窗口应从“传感器 Frame Sync 输出”证据中排除：COMPARE0 经 GPPI 连接 **P1.02 的 GPIOTE SET**，COMPARE1 中断随后读取六个按键 GPIO 并提交按钮/报告工作。它支持按键采样相关门控的判断，没有证据证明是传感器成帧触发。P1.02 的实际电气负载仍需 PCB/原理图确认。

固件会按速率和 DPI 选择传感器寄存器表；但没有匹配的私有传感器寄存器定义，不能把候选配置位命名为 FrameSync，也不能声称已经还原内部曝光时钟、成帧时间或与 USB 的相位锁定。

## 证据身份和地址映射

- 原镜像：`firmware-extracted-1.20/Suit2FWData__radio_radio.bin`，201044 字节，SHA-256 `c817c565857059f19092737922aa43c8e1badf0701b675c777a6e721e486af48`。
- 原始指令导出：`analysis/mouse-radio-1.20-final/disassembly.txt`；同目录 `.c` 仅为推断反编译，不是原始源代码。
- ROM：文件偏移 `VA−0x0E06C000`。RAM 代码：`VA−0x23020000+0x79C`，长度 `0xC6B0`。
- 初始 RAM 数据：`VA−0x23000000+0x2F888`，仅覆盖 `[23000000,23001878)`；启动复制常量 `0E096424..42F` 为 `23000000,23001878,0E09B888`。
- 本地 Nordic 两份 SVD 确认：`5F9C2000=GLOBAL_TIMER134_S`、`5F9B2000=GLOBAL_TIMER132_S`、`5F9B5000=GLOBAL_SPIM132_S`（同地址也有复用外设视图，ENABLE=7/PSEL/DMA 操作确定此处使用 SPIM）。旧模型的变量名不能改变外设身份。

JSON 的 `raw_evidence` 每段给出地址、文件偏移、字节、SHA-256 和原反汇编行号；`literal_evidence` 给出间接路径所需的原描述符内容。无需依赖反编译器的自动命名即可复核。

## 读取链和精确调用点

| 阶段 | 原指令/数据证据 | 行为与边界 |
|---|---|---|
| 注册运动工作 | `2302A74C..750`，字面值 `23006778,2302A719` | `work_init(6778,2302A719)`；`2302A718` 是到 `23026DA0` 的 B.W |
| 提交工作 | `230287B6`；另有 `230284EC` 对应路径 | 比较运动输入 P2.04 与极性位；命中或保留轮询条件后提交6778。提交不证明工作立即执行 |
| 回调开关 | `23026DA0..DA6` | byte `230077AA=0` 时直接返回 |
| 读传感器 | `23026DAA BL23028290` | 后续把读出的增量累积到76D6/76D4 |
| 互斥 | `230282A2/23028334 ->2302C3B0->0E094C5C` | 对6788尝试加锁；timeout64=0；忙则返回，不读取 |
| 命令和长度 | `230282AC..B2` / `2302833C..42` | `r0=0x16,r1=SP,r2=6/12`；12字节仅当77A7==1 |
| SPI | `2302A8A8` | 7746必须非零；7745为零时才调用AC40准备DMA |
| 结束与拷贝 | `2302A8EA`轮询；`2302A920 ->2302C608->0E09739C` | 等SPIM+108 END非零，释放CS，清END，从2FC13002复制指定长度 |

**缓存边界：**7745非零时没有检查本次寄存器/长度是否与上一次一致，直接复用DMA设置。7746是SPI初始化标志，也是A8A8的返回值，并非数据校验/帧有效位。读取函数的END等待没有超时；原指令不能被替换成自动成功。

**数据解释边界：**28290只在payload[0].bit7为1时，把LE16(payload+2)存76EA、LE16(payload+4)存76E8；bit2、bit3分别存77A6、77A5；bit5存1509。状态byte1还检查 `(value&0xF7)==0xB7`，异常会触发恢复路径。上述是代码层含义，未取得传感器datasheet时不能赋予完整的帧/曝光术语。

12字节分支在 `23028386` 另读 `SP+0xC`，写77B2；这超过复制的0..11字节，是原始栈残留，不能解释成可靠的第13个传感器字段、帧编号或时间戳。反编译把诊断字段更新顺序表达得混乱，原指令显示它们在成功返回检查之后才更新。

`26DA0`以半字累积76EA/76E8到76D6/76D4，或在4A50==1时调用23020000转换后累积；mode7723==1另受777F/7788抑制条件影响。回调最终清瞬时增量；1505==0x55且累计位移非零时把半字76D2 OR4，否则清累计值。此处没有可识别的曝光时间戳。

## SPI 和 GPIO 原始配置

初始化数据 `230004D8` 对应文件偏移 `0x2FD60`，原字节 `00 50 9B 5F`，即SPI基址 `5F9B5000`。

`2302AD18` 写入：

| 地址（基址+偏移） | 值 | SVD意义 |
|---|---:|---|
| `5F9B5600` | 0x43 | SCK=P2.03 |
| `5F9B5604` | 0x46 | MOSI=P2.06 |
| `5F9B5608` | 0x45 | MISO=P2.05 |
| `5F9B560C`, `5F9B5610` | FFFFFFFF | DCX、硬件CSN断开 |
| `5F9B552C` | 2 | PRESCALER；不据此单独推算实际SCK频率 |
| `5F9B5554` | 6 | MSB first，CPHA=1、CPOL=1，即mode3 |
| `5F9B5500` | 7 | SPIM ENABLE |
| `5F9B5108` | 0 | 清EVENTS_END |
| `23007746` | 1（byte） | 初始化标志 |

原函数还写+5B8=0、+5B0=2、+5C0=0、+5AC=1及+308=4；它们的精确存储保存在JSON，不给未知功能另起“帧触发”名称。特殊基址5F8E6000/7000时PRESCALER=0x28，当前镜像默认基址走2。

`2302AC40(reg,n)`：2FC13040=reg&7F、2FC13041=0，TX.PTR(+73C)=2FC13040、TX.MAXCNT(+740)=2；RX.PTR(+704)=2FC13000、RX.MAXCNT(+708)=n+2；清END，7745=1。SPI DMA缓冲区地址合法性检查/日志分支也存在，详见原指令。

`2302A8E4`写SPIM.TASKS_START(+0)=1；`2302A8EA..F0`只轮询END(+108)。这个END在SVD中明确是TX/RX缓冲区传输完成，不能当作传感器的“新帧完成”。

| MCU引脚 | 来源 | 可确认用途 |
|---|---|---|
| P2.07 | ROM `0E09AC38+4/+8={0E09782C,7}`，GPIO基址5F938400 | 软件CS；初始化A56C清707C.bit7，普通路径A8A8先OUTCLR80、结束OUTSET80，极性位非零时反向 |
| P2.04 | 同描述符+0C/+10 | 运动读取条件输入；28760读端口IN并按707C.bit4极性判断，命中时提交6778 |
| P2.01 | 同描述符+14/+18 | E0849BC初始化脉冲/控制，脉冲间调用sleep；物理“reset”命名尚未由引脚资料证实 |
| P2.03/.06/.05 | AD18 PSEL原值43/46/45 | SPI SCK/MOSI/MISO |
| P1.02 | 2663C的全局pin0x22与GPIOTE CONFIG | Timer132的按键采样相关门控，区别于以上传感器总线引脚 |

GPIO驱动表 `0E09B3A8` 的+0C=`230263BD`写OUTSET、+10=`23026369`写OUTCLR、+04=`230263AD`读IN。P2对象E09782C最终指向5F938400；P1对象E097840指向5F938200。

在已检查的周期读取路径中，只有CS边沿、SPI START/END与运动输入判断；P2.01脉冲出现在初始化E0849BC。此为有界静态结果，不等于证明所有隐藏传感器模式都没有外部同步。

## Timer132：为什么不能当作传感器成帧

`2302B5C8`成功配置16MHz计数、32位BITMODE3、PRESCALER0和IRQ0x1B2(priority4)后置byte774C=1。`B678`反初始化并清774C，`B4E8`仅在774C非零时STOP/CLEAR并重配。**774C不是frame-ready。**

B504计算微秒参数d：

| 条件 | d |
|---|---:|
| mode7723=1，rate4A5F<8 | rate×125−95 |
| mode7723=1，rate>=8 | 700 |
| mode=4，779E非零，rate4A5D<8 | rate×125−95 |
| mode=4其他条件 | 700 |
| 其他mode | 0 |

只有d不同于word4CE4才重写。初始化先把4CE4清零，因此“其他mode d=0”可能不重写CC。rate=0在原指令算出−95，其32位无符号换算是异常输入域，不能展示成合理的负延迟。

重配先清CC0..5、SHORTS &=FF00FF00、INTENCLR=00FF0000。helper29E1C对当前16MHz/PRESCALER0得到 `ticks=16×us`。CC0=d（关COMPARE0中断），CC1=d+30（开COMPARE1中断）；SHORTS的0x20000是 **COMPARE1_STOP**，不是SPI自动读取。典型d：rate1=30、rate2=155、rate4=405、rate>=8=700微秒。

`2302663C`注册的硬件路径：

1. GPIOTE130描述符E0991B0的base=5F934000；channel来自byte773D（动态分配，不能写死）。
2. pin0x22=P1.02；MODE=3(Task)、PSEL=2、PORT=1、POLARITY=3、OUTINIT=0；对应CONFIG通常是0x30223，前提是正常通道配置成功。
3. GPPI handle来自byte773A，源事件 `5F9B2140`（Timer132 COMPARE0）；目标由29600返回 `5F934030+4×channel`，SVD定义为 **TASKS_SET**。
4. COMPARE1触发ISR `2302B224`，清5F9B2144，读取P1.05、P1.04、P1.10、P2.10、P2.11、P1.03并拼成六位输入，存halfword1502和76D0。
5. `2302B35A ->2944C`把同一GPIOTE.CONFIG.OUTINIT bit20置0；`2302B360`提交work6764，回调26CA4。

这里比较点间隔确为30微秒；低电平相关配置写发生在IRQ执行后，不能忽略中断延迟而宣称实测高脉冲严格30微秒。该引脚与按键采样流程相连，实际是供电、发光或其他使能仍待电路证据；没有传感器曝光证据。

## Timer134和774B的边界

774B由B890配置Timer134成功后置1、B944反初始化清0，表示Timer134已初始化。BA74使用rate4A5F：rate1在90/215/340/465微秒比较，rate2在10/260微秒比较，其他在10微秒比较；经29E1C换算为计数。B3D0 IRQ再到28760，并可能启动Timer132、提交传感器读取工作。**它不是SPI基址，774B也不是传感器帧标志。**周期源、无线排队和接收器USB相位由主报告继续衔接，此处不重复扩展。

## 传感器配置：数值可追溯，功能名称未知

原写寄存器函数 `2302AB40` 在CS有效期间发送 `[reg|0x80,value]`，TX count2/RX count0，启动SPI；清7745使下次burst重新设置。它轮询END，调用短延时并以7692计数限制重试；成功/失败均释放CS。所有下面的配置最终经过这条写路径。

初始化E0849BC有CS/控制引脚序列，写 `0x3A=0x5A`、`0x19=1`，轮询寄存器0直到值0x6A或0x59，调用E07FA38大表，读0x02..0x06，按7716选择E0847F0/E084820，再写0x68=1及调用其他配置。没有原厂引脚/寄存器表时，识别码不等于完整型号证明。

| 入口 | 原指令确认的数值行为 | 不能推出的结论 |
|---|---|---|
| `0E0802E4(arg)` | 7F=0D；48=FD(arg==1)否则FC；7F=0 | bank0D/reg48.bit0的真实名称未知，不可直接命名FrameSync |
| `0E0847F0` | 读reg40，写回OR80 | 继承bank；正常初始化在bank0。bit7名称未知 |
| `0E084820` | reg40 AND7F；77..7C写3F60、3F5C、3F58各低/高字节 | 不把这些参数直接命名帧周期/曝光 |
| `0E08494C(arg)` | bank5：arg==1时78=80、77=4A53，否则均0；恢复bank0 | 私有功能未知 |
| `0E0844C0` | 按mode/rate与两个16位4A8C配置值的4000/10000阈值选择表，随后调用802E4(1) | 说明配置随速率/DPI变化，不证明曝光与报告锁相 |

E0844C0有效域是77AA非零、mode为1或4；各列分别是两个配置值均<=4000、均<=10000、其他：

| 运行条件 | 低档表 | 中档表 | 高档表 |
|---|---|---|---|
| mode4，或mode1且rate<=1 | E083794 | E083BF8 | E08405C |
| mode1 rate2 | E082170 | E0825DC | E082A48 |
| mode1 rate3/4 | E08142C | E081898 | E081D04 |
| mode1 rate>4 | E0806E8 | E080B54 | E080FC0 |

表选择和802E4调用已经核对原指令；JSON另保存12张表的**反编译候选数值清单**，有缺失参数时保留null，没有冒充逐项原字节验证。每张表有136个写调用，无法仅靠未命名的数值确定哪一个控制成帧。厂商命令E07CC50/op32也能写bank0D/reg48=CC等测试配置，进一步说明不能把FD/FC一位差异直接视为唯一的FrameSync开关。

## 尚未闭合的 Frame Sync 证据

- 未取得与本镜像传感器相匹配的寄存器定义、曝光/帧时钟说明、PCB网络命名。
- 未见可信的帧计数/曝光时间戳在本读取链中传递；0x16与SPI END不能替代该证据。
- 软件工作队列、mutex忙返回、SPI轮询都有时延/条件，静态调用图不能证明每个报告取到恰好一帧或没有相位抖动。
- 可以继续利用原厂寄存器定义验证候选位，或在另行授权的实机测量中同时记录CS/SCK/P2.04/射频/USB时间。当前没有执行任何这种测量，不能将本报告写成端到端Frame Sync已验证。
