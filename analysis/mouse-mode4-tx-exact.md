# 鼠标 1.20 mode4：真实 TX 选包与编码扩展

## 验证结果与接口

新增 `mouse_mode4_tx.c/.h`，恢复 `23024918` 的 idle/action3 正常输入域，接入 `2302516c` 定时入口。新增 **4,352 组原 Thumb/C 对照全部 PASS**，6 项布局边界检查 PASS；旧 3,072 组与 8 项边界以及旧连续组件全部通过。没有修改原始指令，没有目标函数桩，也没有 CPU userop getter 补丁。这里的“完整 TX 入口”仅指有效初始化队列和本文列出的 RAM 域；整个 mode4 无线栈仍未全部完成。

- `rr_mouse_mode4_tx(ram,radio,timer)`：直接执行 idle/action3；其它状态自然返回。
- `rr_mouse_mode4_action_full(ram,radio,timer,action)`：新 TX 路径与既有动作统一入口。
- `rr_mouse_mode4_timer_full(ram,radio,timer,spim,nvic)`：真实 CC1 → action3 → 选包/编码；其它事件继续已有恢复。
- 旧 `rr_mouse_mode4_action` / `rr_mouse_mode4_timer` 保持原分析 API 的 `-4` 边界，旧测试与数据完整保留；full 后缀不表示真实硬件或所有生命周期都已完成。

宿主需提供 RAM `23000000..2300ffff`、RADIO `5302c000`/4096 字节、TIMER `53028000`/1536 字节。有效环队列容量/步幅/读写索引/指针是前置条件。TX 对 bank>2、selector2/3 信道索引>36、错误队列布局返回 -9；该值是分析边界，不是固件错误码。直接 action 的 -9 在修改前返回；timer_full 可能已经消费事件/更新 slot 才遇到布局边界，接口注释已说明。

## 精确恢复的选择逻辑

槽 0/3 使用 TXEN 订阅，槽 1/4 与其它路径使用 START 订阅。rate2 会依据 `27c8` 与缓存锁 `2670` 更新 `27c7`。非活动窗口根据所有队列空状态、`29d0` 及 `29d1+bank` 判定：全局状态3的门限4，其余状态门限16。这些分支有自然 no-op；不会凭空产生成功发送。

普通选择在事件计数 `2a0a` 为奇数时先扫描队列2..5，之后扫描0..5。slot3 存在 motion 缓存时优先查看队列1。所有 peek 实际标记条目的状态字节；正常业务队列保留至 ACK。rate<3 的队列1聚合路径则在发送准备阶段调用实际 pop，这是与其它队列不同的生命周期。

`23025020..23025142` 将 buttons 与 `2a19` 及旧 buttons OR；wheel 作8位累加；X/Y 从包内 BE16读取后与 `2682/2684` 的16位累计值相加，再以 BE16写回。源包前9字节保存到 `2672`，置缓存标记 `2671`。rate1/slot4 或 rate2/slot3 锁定缓存 `2670`；其它相关槽在缓存未锁时清 reply 请求。聚合后的本次发送继续使用刚弹出条目的包指针；后续缓存重发复制9字节到 `2a76`，其余旧尾部保持。

正常选包写 `2a1a`，清 bank 活跃计数 `29d1+bank` 和 `2a10`，上行 byte1 为 `(reply<<7)|(link_sequence<<4)|failure`。失败字段在 selector0/1 读取 `2a14+2*bank`，selector2/3 读取 `289e+2*2792`，饱和到15，其它 selector 返回0。原 helper 不额外掩码输入序号/reply；C 保留8位存储截断。

没有可用数据时产生 `17` 状态体：源长度5、独立 body 序号 `2a2a`（恰为8时回1）、BE16 的 `2a10`，队列号255，并请求回复。状态体不清 `2a10`。

## 编码与特殊帧

普通路径 `23024baa..23024bf4` 先复制全部16字节到 `2650`，设置 PACKETPTR，再按原 byte0 长度对 byte1..length 求8位和，写入负和，最后把长度加1并8位截断。该顺序依据原汇编，避免 Ghidra 全局别名造成的伪顺序。**原函数没有“长度最多15”检查**：较长 length 会读本次16字节复制范围之外的旧 RAM，长度255会使输出长度回绕为0。恢复代码与原始指令一致地保留这一行为；它不是有效无线帧的承诺。4352条记录包含351个正常输出长度0/17/32的结果。

特殊低活动帧 `23024a28..23024a62` 只写 DMA前三字节 `02 55 00`，保留其余旧尾部，绕过普通负和编码。128个额外针对性用例实际生成此帧，另外128个用例走自然 no-op。用途仍未知，不能给它自动添加校验，也不能称其已经完成实机互操作。

发送准备最后捕获 CC7。普通路径 slot0 要求 >99、slot1 ≤100、slot3 ≤250、slot4 ≤350，其他 slot 无该门限；超时撤掉 TXEN/START、保持 idle。及时准备成功置 TX 状态19，依据 reply 是否恰为1安装或清 RXEN 订阅。特殊帧只在 slot0/3 生成，失败只撤 TXEN，不清旧 START/RXEN；这一差异在全寄存器对照中保留。

## 原始指令对照证据

| 数据 | 数量 | 内容 |
|---|---:|---|
| mouse-mode4-tx-original.jsonl | 4096 | 3072 个直接 idle/action3 + 1024 个 TIMER CC1→TX |
| mouse-mode4-tx-special-original.jsonl | 256 | slot0/3 特殊短帧、slot1/4 自然 no-op与时限边界 |
| 合计 | 4352 | 全部RAM、RADIO、TIMER、SPIM、NVIC快照逐字节一致 |

`EmulateMouseMode4Tx.java` / `EmulateMouseMode4TxSpecial.java` 在只读 mouse120 原项目执行目标指令，校验原镜像 SHA256 与 LMA→VMA 全切片一致。映射为原镜像偏移79c到 `23020000`，长度c6b0。源码依据包含顶层反编译 `2302243c.c` 与已保存的 `23024918..2302516c` 汇编片段。对照检查的状态是全部65536 RAM、4096 RADIO、1536 TIMER、16 SPIM字节及 NVIC 最后写值；不模拟真实 MMIO 事件副作用。

原记录的结果统计：2481次准备DMA，其中2353普通编码、128特殊短帧；1987次进入TX状态、494次因时限取消；1871次未准备包；120次 motion队列提前pop。普通包确实覆盖队列0..5与255缓存/状态源。结果统计不是“全部路径覆盖”的证明。

## 实际生成双向 DMA 的连续组件

`test_mouse_mode4_tx_integration.py` 将真实鼠标 class0 enqueue→TIMER CC1→TX DMA 传给恢复后的接收器 IRQ/业务 SWI，接收器再从真实 class3队列产生下行，进入鼠标 RX→业务重组→adaptive。没有环境合成的上行 payload。

8场景 ×32周期共256个鼠标生成上行、256个接收器生成下行；接收器3072次定时事件、256次扫描IRQ；鼠标768次定时事件。192次成功下行完成业务且pop上行队列，64次CRC失败保持读指针和链路序号；其中56次在下一周期产生相同业务体/相同链路序号的真实重发（每场景末尾一次失败没有下一周期）。射频CRC、TX完成、RX/DISABLED及扫描完成事件仍是显式环境输入；这是软件组件链，不是PHY仿真。

旧8场景组件仍保留并复验，含80次业务重复拒绝。新组件没有额外重复注入，也不将它计为新的原指令用例。消费者继续真实延期，work.flags=4自然fast-return；无 RTOS成功桩。

## 当前未完成边界

- mode4 class3非空ACK回调仍为显式边界，未接入其它已恢复的timer lifecycle模块。
- slot5超时断开、待速率更新、selector2/3频表重算仍沿用旧边界。
- 初始化/DPPI全链、异步中断与DMA并发、真正RTOS调度、空口白化/CRC比特流及实机射频未由此验证。
- 普通发送函数写 PACKETPTR/订阅寄存器仅证明“准备发送”；硬件是否发送由外部事件决定，测试不自动补成功事件。
