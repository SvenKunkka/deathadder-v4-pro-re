# 鼠标 1.20 state 0x17 终态生命周期

已新增独立 `recovered-code/portable/mouse_lifecycle.c/.h`；原 `mouse_handshake.c/.h`、Python 握手模块和公共验证脚本未修改。终态无线初始化及实际连接成功工作项回调均已恢复，**528 组原 Thumb/C 差分通过**。活动定时器与线程调度仍有明确边界，不能据此声称整个生命周期或完整 2.4 GHz 固件已恢复。

## 1. 原始入口的调用顺序

`230227B8` 仅在 u32[23002A04]==0x17 且 event==5 时执行：

1. RADIO SUBSCRIBE_TXEN=0，TIMER020 SUBSCRIBE_CLEAR=0。
2. 若 u32[2300298C] 非零：清此 pairing flag，构造栈参数调用 `23025F44`；**该函数原始机器码就是 BX LR，参数无副作用**。随后 `23021C40(0,u32[230027B0])` 把身份写入 u32[230027AC] 和 RADIO BASE1[5302CE30]，补码写 u32[230027B4]。
3. `23021BF8(0)` 设置 TXADDRESS=1；`23021BB0(0)` 设置 RXADDRESSES=0x0A；`230217F0` 再清 TIMER SUBSCRIBE_CLEAR。
4. 对定时器对象 23001540 连续调用两次 `0E096AC4`。
5. 依据 u16[23002798] 选择初始化：2→23023544；1→23021A7C+230244CC；4→23021A7C+23025778；其它值不进入模式初始化。
6. 构造包含 mode 的局部参数，调用 `23025DC0`。它先停止 timer23001578；若 u16[23006B7E] 已非零则返回。否则置该字段为1、把 mode 写到 u16[23006B82]，向 work230067C0 提交工作。

这里的 pairing 标志清零、BASE1 写入和工作项提交均不能称为“写入持久配对”。已确认的直接路径没有闪存保存调用。

## 2. 模式初始化

三种模式共同写 u32[23002978]=3、u16[23002794]=3、byte[23002A1F]=FF，u16[23002A0A] 加5（16位回绕），清 u32[23002A10]/[23002A14]、u16[23002A0C]/[230029A8]；最终清 230029B4..230029CC 共7个word。TIMER CAPTURE7 subscribe=byte[230076EF]|80000000。

| mode | RADIO SHORTS | INTENSET00 | RADIO MODE | TIMER CC2 | u16[2300283C] |
|---|---:|---:|---:|---:|---:|
| 2 | 80001 | 100 | 4 | 300 | 2 |
| 1 | 1 | 14E | 4 | rate==1 ? 395 : 390 | rate==1 ? 4 : 3 |
| 4 | 1 | 140 | 9 | 415 | 5 |

rate 是 u16[230029AC]；以上寄存器数值除 CC2 十进制外按十六进制列示，不能据此自行给 CC2 赋时间单位。三种模式都先向 INTENCLR00 写 FFFFFFFF。mode2 通过 23021B90 设置无线 state=18、清 READY/END/DISABLED 并 TASKS_DISABLE=1；mode1/4 只直接写 state=18，不能替它们补上 mode2 的清事件/disable 动作。

mode1/4 先将 u32[230027B4] 写 RADIO PREFIX0，并依照 23002620 起13个配置字节组装 PCNF0、PCNF1。mode4 还设置 u32[23002A00]=18、u16[230029FA]=5，并用 rate==4 或 rate>7 决定 byte[230029F9]。

`23021AF8` 设置 MODE 后还写7个调校 word（8A4/8A8/8AC/7AC/7B0/7B4/7E4）；8A0 只有原值80000000或0058120E才改为0058090E。数值已按机器码保留，未推测未公开寄存器的物理含义。

selector=u16[230027A2] 为2或3时，23022264→23021D6C 展开 230026B9 起5字节位图的最低37位：已启用项生成索引序列和原频道编号；23002712 起37字节记录原编号或FF；count存byte[23002737]；u16[230026C6] = BASE1高低半字异或。未使用的列表尾部保留旧值。

## 3. 真正的延期通知回调

`23025D1C` 用 0E0952A0 将 work230067C0 的 handler 设置为 Thumb 23025DF1。该函数调用 `23020E7C(1,pending==1)`。恢复的第二个入口 `rr_mouse_lifecycle_connected_work` 实现 pending==1 的连接成功分支：

- u16[230076E0]=1，byte[2300771F]=1。
- 若 byte[23007748] 与 byte[23007747] 都非零，2302B74C 停止 timer23001B48，再清 byte[23007747]。
- byte[23007788]=2，byte[2300777F]=1。
- 0E07EFAC 仅在 775C、775D 两字节均零时设置它们为1、7741..7743为FF、u16[769C]=0、byte[775E]=0。
- byte[772C]=1；若 byte[7736] 非零则另设 byte[772D]=1、u16[7690]=0、byte[772C]=0。

此回调**由调用方按调度器真实时机单独调用**；主生命周期函数不立即执行它，不假设队列提交等于回调已经完成。pending!=1 的断开分支不属于此次连接完成恢复，接口返回-4。

## 4. RTOS 与硬件边界

独立 C 入口 `rr_mouse_lifecycle` 的 RAM 输入覆盖23000000..23007FFF，另有 RADIO 0x1000字节和 TIMER020 0x600字节输入输出。支持本轮完成验证的自然条件：

- timer23001540、timer23001578 首word都为0（未激活）。原0E096594在此状态内部返回-22，0E096AC4自然返回；没有替换目标函数。
- u16[23006B7E] 已非零，或 work230067C0 的 flags(+12)&6 非零。后者是在0E09518C自然快速返回，尚未进入调度器。

active timer 不满足时返回-2；可能进入未恢复 work 调度器时返回-3；均在修改任何输出前拒绝。这是**恢复接口的前置检查**，不是原固件返回这些值，也不声称原固件在这些情况下没有副作用。连接成功回调另要求可选 timer23001B48 未激活，否则同样返回-2。

待恢复的活动路径明确为：0E096AC4→0E096594→0E09643C 删除timer链表/重新设时钟，随后 timer+24 回调、0E095D50(timer+18) 等待线程弹出、0E095BD4/0E095ECC 调度；work提交进入 0E0952EC→0E09518C→0E096220 等调度与队列更新。这些不能用空函数代替。下一阶段应恢复这些上下文，并将独立接口接入完整状态机。

## 5. 差分与复验

`EmulateMouseLifecycle.java`：400组（384个event5＋16个其它event），各模式0/1/2/4/8/FFFF、selector0..3、rate1/4/8/FFFF、pairing及pending组合；随机非零 MMIO 初始状态。

`EmulateMouseLifecycleWork.java`：128组连接成功回调，覆盖可选timer取消、775C/775D条件和7736分支。两者使用现代 AdaptedEmulator，执行前核验原固件 SHA-256 及整个RAM复制区；目标函数和辅助函数没有打桩。

Ghidra ARM 库缺少 getBasePriority getter，验证脚本采用现有通知验证的方式桥接到**同一个内置 ArmCpuState**，不是另造优先级值。测试初始 BASEPRI=0/20/80，原指令执行后均恢复。ISB 在 Ghidra 内仍是 TODO/no-op；日志保留该警告，结果不证明屏障、IRQ抢占或外设真实时序。

`verify_mouse_lifecycle.py` 编译独立 C，逐字节比较每组全部32768字节 RAM、4096字节 RADIO、1536字节 TIMER（回调还确认两外设窗口完全不变）。528组全部通过，另4个接口前置拒绝测试通过。结果和源代码哈希在 `mouse-lifecycle-comparison.json`；原始指令区间、字节及哈希在 `mouse-lifecycle-evidence.json`。堆栈局部内容、CPU周期和调度器未在C比较对象内。

本轮验证没有写设备，也没有安装或执行更新器。完整2.4GHz目标仍需活动RTOS上下文、所有中断/调度连接及实机时序验证，不能以本模块通过作为整个固件恢复完成。
