# 鼠标 1.20 业务消费者 23025E38

已新增独立 `mouse_business_consumer.c/.h`，复用现有 `business_tx` 的完整碎片/环形队列实现；生命周期模块及其它共享代码未修改。**512 组未改写原 Thumb / C 差分全部通过**，包括实际可以执行到返回的辅助函数。RTOS timer start、非返回重启和活动传感器初始化仍有明确接口边界。

## 输入与校验

入口没有业务参数，读取 byte[2300779B] class、byte[2300779C] n、230067D0 起缓冲区。除 AC 特例外，将全部 n 字节相加取低8位，和非零直接返回；n=0 跳过校验。随后尾调用 `23020F0C(class,buffer,(uint16)(n-1))`。不能给原固件补上最短帧长检查：A3/B1 等分支会直接读固定偏移，即使 n 为零也可能读取旧缓冲内容。

**class3 且首字节 AC 在 checksum 之前处理**：23025948 总是返回1，因此不会继续校验，也不会执行末尾连接状态同步。它把 payload[1:3] 组成大端16位参数传给23021C58，但后者只做一字节写，实际 byte[230029E0]=payload[2]。原两字节任意非零时，响应为 `[AC, quotient]`，quotient=(6B88低16位 / 高16位)低8位；分母零时为0。清 u32[23006B88]，经23025AB0发送 class3、长度2响应，清 u32[23006B68]。环队列满的拒绝行为由原TX模块保留。

## class3 A3

先清777F，再调用0E07EC54清一组连接状态字节；u16[76E0]=0、777F=0，向5F9C2004和5F9C200C写1，并清7796、771F。2302B70C仅在7748非零且7747为零时进入timer start；该分支仍待RTOS恢复，独立接口返回-2且保留输入。其它上下文自然返回，不是空函数代替。

当7723==1，0E07EEE8清7741..7743、775D/775C/775A/7759/775B、u16[76C4]/[769E]，最后775E=1（前面的0E07EC54已令775E=0）。之后执行共同状态同步。这里没有调用 lifecycle 的“连接成功”回调；两条路径的语义相反，不能为了复用而混用。

## class3 B1

u16[76E0]==0 时原代码进入0E085ED0重启/无限循环路径。恢复接口返回-4，不把它伪造为正常返回。

正常分支：payload[1]控制7775及其保存值7774；payload[4]控制7773及保存值7772。当前rate=byte[4A5F]小于8时可强制目标7781=8并置7776；相应标志撤销时按保存值恢复目标。payload[4]还写7771，payload[5]写7796。

接着23021278发送8字节class3响应：`B1 00 BF 00 byte[4955] old_rate byte[4A62] byte[7733]`，然后23025C70→23021C6C处理**旧rate**，时序在实际切换4A5F之前。若rate不在1..64，该辅助直接返回；否则：

- u16[2794]<3或u16[29AC]==0：直接更新29AC；rate==1时可能使能5302E040，离开rate1时可能写5302E044并清76EE。
- 其它情况：通过真实 class0 环队列发送 `2F rate BE16(u16[2A0A]+100)`，并写29AE=rate、29B0=截断后的时间值。队列满仍保留后两处写入。

若7776与771F均非零，调用23026CE0(1,目标7781)，随后清7776。目标与4A5F相同时该辅助自然无修改；不同则写SPIM停止/清除寄存器、更新4A5F、执行配置分支23026BD0并清一组计数/标志。本轮覆盖774B/774C为零时辅助自然返回的路径；如果实际发生rate变化且这两个硬件使能标志非零，需要进入2302BA74或2302B504等未恢复外设代码，接口在任何修改前返回-3。

当7796非零时，773F==1被清零；当7796为零且773F==1时，u16[76D6]=1、u16[76D2]|=1。然后同步共同状态。

## class5 5A：长度不能擅自修正

原代码先将23003EFC起90字节清零，再从payload+2复制 `((uint16)(n-1))-2` 字节，之后把payload[1]写到目的偏移88（23003F54），置7715=1、7797=1，最后执行共同状态同步。

| n | 原始消费者行为 |
|---|---|
| 0 | 跳过checksum，计算复制65533字节；主机接口返回-5，未执行巨大复制 |
| 1 | 唯一字节5A的checksum非零，提前拒绝；后续负长度式不可达 |
| 2 | 第二字节A6可令checksum通过，然后复制长度为FFFFFFFF；主机接口返回-5 |
| 3..255 | 实际复制0..252字节，无90字节截断；本轮最大255也已原指令验证 |

这些是已观察到的固件算式和边界，不是声称存在可利用漏洞。恢复模块在完整64KiB RAM快照内忠实模拟n>=3的写入，包括超过原90字节区域和偏移88的覆盖；没有偷偷截断或将异常长度归零。后续230211DC会组装5A响应，但异步处理/响应发送不属于本入口，本模块不自动提前执行。

## 共同尾处理

checksum失败和AC特例不会到达这里。其它已分发消息（含未知命令/class）检查byte[1508]是否等于byte[7796]；相等不动。不同则复制7796：非零清7795；零则u32[679C]=15000、byte[7795]=1。不能把未知命令解释为完全无副作用。

## 验证与接口边界

`EmulateMouseBusinessConsumer.java` 从原23025E38执行，核验完整原flash及RAM拷贝，没有替换目标辅助函数、没有CPU userop补丁。512组分为8类各64组：AC非零/零参数、A3、B1、5A、class3未知、其它class未知、坏checksum。包含n=0旧缓冲路径、5A最大252字节复制、TX空位0/1/31、DPPI直接rate切换和class0延后rate协商。

`verify_mouse_business_consumer.py` 以C11严格警告选项编译新模块和现有TX/cipher，逐字节比对全65536字节RAM、SPIM16字节、DPPI72字节；512组均通过，另5个边界前置拒绝测试通过。原始记录与所有源文件哈希保存在 `mouse-business-consumer-comparison.json`，函数区间及机器码哈希在 `mouse-business-consumer-evidence.json`。

新接口负值是主机侧分析域的前置拒绝，保证输入不变，**不是原固件返回值或原固件在该处没有副作用**。调用者须按business_tx.h提供有效环队列字段/地址。本轮未恢复活动RTOS timer、重启以及使能后的传感器重初始化，未验证真实PRIMASK/中断交错和设备时序。未写设备；mouse120已释放。
